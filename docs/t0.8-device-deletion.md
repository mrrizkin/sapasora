# T0.8 device deletion lifecycle

Device deletion now disconnects the provider, removes every non-deleted device token, and only then soft-deletes the device. A failed cleanup step leaves the device available for a later retry; completed deletion is idempotent for the same device object.

## Audit/event blocker

The codebase has no application audit/event abstraction for domain lifecycle events (the existing `fxevent` logger is framework lifecycle logging only). T0.8 therefore does not add a new event system. A `device-deleted` audit event remains blocked until the existing audit/event contract is defined.

Provider outbound work has no shared queue/admission gate. The coordinator uses the existing `GatewayService.Disconnect` boundary first; adding a new cross-provider work gate is outside T0.8.
